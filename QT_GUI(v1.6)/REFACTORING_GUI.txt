1단계: .enc 확장자 처리 중복 제거

【작업 내용】
- mainwindow.cpp에서 .enc 확장자 처리 로직이 여러 곳에 중복되어 있던 것을
  유틸리티 함수로 통합하여 코드 중복을 제거하고 유지보수성을 향상시킴

【문제점 분석】

1. .enc 확장자 체크 로직 중복
   - 위치: 6곳 (159, 241, 290, 356, 383, 516줄)
   - 패턴: filePath.endsWith(".enc", Qt::CaseInsensitive)
   - 문제: 동일한 체크 로직이 여러 곳에 반복됨

2. .enc 확장자 제거 로직 중복
   - 위치: 6곳 (241, 290, 356, 383, 516줄)
   - 패턴 1: baseName.chop(4) - 1곳
   - 패턴 2: baseName.left(baseName.length() - 4) - 5곳
   - 문제: 두 가지 방식이 혼재되어 있고, 매직 넘버 4가 하드코딩됨

3. .enc 확장자 추가 로직 중복
   - 위치: 2곳 (351, 402줄)
   - 패턴: baseName + ".enc"
   - 문제: 매직 문자열 ".enc"가 하드코딩됨

4. 매직 값 사용
   - 매직 넘버: 4 (".enc" 길이)
   - 매직 문자열: ".enc" (16곳에서 사용)

【추가된 함수】

1. isEncryptedFile()
   위치: mainwindow.h (선언), mainwindow.cpp (구현)
   기능: 파일 경로가 .enc 확장자를 가진 암호화 파일인지 확인
   시그니처: static bool isEncryptedFile(const QString &filePath);
   반환값: .enc 확장자가 있으면 true, 없으면 false
   
   구현:
   ```cpp
   bool MainWindow::isEncryptedFile(const QString &filePath)
   {
       return filePath.endsWith(".enc", Qt::CaseInsensitive);
   }
   ```

2. removeEncExtension()
   위치: mainwindow.h (선언), mainwindow.cpp (구현)
   기능: baseName에서 .enc 확장자를 제거
   시그니처: static QString removeEncExtension(const QString &baseName);
   반환값: .enc 확장자가 제거된 baseName
   
   구현:
   ```cpp
   QString MainWindow::removeEncExtension(const QString &baseName)
   {
       QString result = baseName;
       if (result.endsWith(".enc", Qt::CaseInsensitive)) {
           result.chop(4);  // ".enc" 제거
       }
       return result;
   }
   ```
   
   개선점:
   - 두 가지 제거 방식(chop vs left)을 chop(4)로 통일
   - 매직 넘버 4를 함수 내부로 캡슐화

3. addEncExtension()
   위치: mainwindow.h (선언), mainwindow.cpp (구현)
   기능: baseName에 .enc 확장자를 추가 (이미 있으면 그대로 반환)
   시그니처: static QString addEncExtension(const QString &baseName);
   반환값: .enc 확장자가 추가된 baseName
   
   구현:
   ```cpp
   QString MainWindow::addEncExtension(const QString &baseName)
   {
       if (baseName.endsWith(".enc", Qt::CaseInsensitive)) {
           return baseName;  // 이미 .enc가 있으면 그대로 반환
       }
       return baseName + ".enc";
   }
   ```
   
   개선점:
   - 중복 추가 방지 로직 포함
   - 매직 문자열 ".enc"를 함수 내부로 캡슐화

1. performEncryption()
   위치: cryptoworker.h (선언), cryptoworker.cpp (구현)
   기능: 암호화 공통 로직을 수행하고 성공 여부를 반환
   시그니처: bool performEncryption(const QString &inputPath, const QString &outputPath, 
                                   int aesKeyBits, const QString &password);
   반환값: 성공 시 true, 실패 시 false
   
   구현:
   ```cpp
   bool CryptoWorker::performEncryption(const QString &inputPath, const QString &outputPath, 
                                        int aesKeyBits, const QString &password)
   {
       // Windows 네이티브 경로로 변환 (구분자 통일)
       QString nativeInputPath = QDir::toNativeSeparators(inputPath);
       QString nativeOutputPath = QDir::toNativeSeparators(outputPath);
       
       // QString을 C 문자열로 변환
       QByteArray inputBytes = nativeInputPath.toUtf8();
       QByteArray outputBytes = nativeOutputPath.toUtf8();
       QByteArray passwordBytes = password.toUtf8();
       
       currentFileName = inputPath;
       
       // 암호화 실행 (콜백 전달)
       int result = encrypt_file_with_progress(
           inputBytes.constData(),
           outputBytes.constData(),
           aesKeyBits,
           passwordBytes.constData(),
           progressCallback,
           this
       );
       
       return (result != 0);
   }
   ```

2. performDecryption()
   위치: cryptoworker.h (선언), cryptoworker.cpp (구현)
   기능: 복호화 공통 로직을 수행하고 성공 여부를 반환
   시그니처: bool performDecryption(const QString &inputPath, const QString &outputPath,
                                   const QString &password);
   반환값: 성공 시 true, 실패 시 false
   
   구현:
   ```cpp
   bool CryptoWorker::performDecryption(const QString &inputPath, const QString &outputPath,
                                        const QString &password)
   {
       // Windows 네이티브 경로로 변환 (구분자 통일)
       QString nativeInputPath = QDir::toNativeSeparators(inputPath);
       QString nativeOutputPath = QDir::toNativeSeparators(outputPath);
       
       QByteArray inputBytes = nativeInputPath.toUtf8();
       QByteArray outputBytes = nativeOutputPath.toUtf8();
       QByteArray passwordBytes = password.toUtf8();
       
       char finalPath[512];
       memset(finalPath, 0, sizeof(finalPath));  // 초기화
       
       currentFileName = inputPath;
       
       int result = decrypt_file_with_progress(
           inputBytes.constData(),
           outputBytes.constData(),
           passwordBytes.constData(),
           finalPath,
           sizeof(finalPath),
           progressCallback,
           this
       );
       
       return (result != 0);
   }
   ```

【기술적 배경】

경로 변환 후 UTF-8로 변환하는 이유:
1. Qt (C++) 세계: QString (유니코드 문자열, 내부적으로 UTF-16)
2. C API 세계: const char* (바이트 배열 필요)
3. 변환 필요: 두 세계를 연결하기 위해
4. UTF-8 사용 이유:
   - 모든 유니코드 문자 표현 가능 (한글, 이모지 등)
   - 크로스 플랫폼 호환성 (Windows, macOS, Linux)
   - Windows API 호환: MultiByteToWideChar(CP_UTF8, ...)로 처리
   - 현대 소프트웨어 표준

변환 과정:
QString (유니코드) → QDir::toNativeSeparators() (경로 구분자 통일) 
→ toUtf8() (UTF-8 바이트 배열) → const char* (C API 전달)

   ✓ 긴 if-else 체인이 간단한 함수 호출로 변경
   ✓ 함수명으로 의도가 명확해짐
   ✓ onEncrypt() 함수가 더 간결해짐

2. 재사용성
   ✓ 다른 곳에서도 AES 키 길이를 확인할 때 재사용 가능
   ✓ 향후 확장 시 유용

3. 유지보수성
   ✓ AES 키 길이 선택 로직 변경 시 한 곳만 수정
   ✓ 버그 수정 시 영향 범위 최소화

4. 테스트 용이성
   ✓ 헬퍼 함수를 독립적으로 테스트 가능
   ✓ 단위 테스트 작성이 용이해짐

5. 일관성
   ✓ AES 키 길이 선택 로직이 한 곳에만 존재
   ✓ 로직 불일치 방지

【파일 변경 내역】

1. mainwindow.h
   - 추가: void resetUIState();
   - 추가: int getSelectedAesKeyBits() const;

2. mainwindow.cpp
   - 추가: resetUIState() 함수 구현 (약 12줄)
   - 추가: getSelectedAesKeyBits() 함수 구현 (약 9줄)
   - 수정: setupUI()에서 resetUIState() 호출
   - 수정: resetUI()에서 resetUIState() 호출
   - 수정: onEncrypt()에서 getSelectedAesKeyBits() 호출

【참고사항】

- 모든 변경사항은 기존 기능을 유지하면서 진행됨
- 함수 시그니처는 변경되지 않아 호환성 유지
- 컴파일 경고 없음 확인 완료
- resetUIState()는 setupUI()와 resetUI()에서 공통으로 사용
- getSelectedAesKeyBits()는 const 함수로 구현하여 상태 변경 없음
